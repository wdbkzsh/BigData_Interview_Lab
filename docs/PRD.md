## 1. 产品定位

**一句话定位**：面向大数据开发校招的个人刷题 + 知识点速记 + 间隔复习工具。

**核心价值**：
- 不是在线教育平台，不是题库网站
- 是一个**只服务于自己**的校招冲刺笔记本
- 解决的核心问题：知识点记不牢、刷过的题会忘、错过的题反复错、复习没有计划

**产品闭环**：

```
学习知识点 → 做题 → 发现薄弱 → 回看知识点 → 重新做题 → 间隔复习
```

**设计原则**：
- 每天愿意打开，而不是被迫打开
- 做一题有一题的收获，不追求题量
- 复习提醒是拉力，不是压力
- 知识卡片服务于快速记忆，不做成课程

---

## 2. 目标用户

**唯一用户**：本人（大数据开发方向，准备校招笔试 + 面试）

**使用时段**：
- 每日固定学习时间（如晚上 2 小时）
- 碎片时间复习（如通勤时看知识卡片或错题）
- 面试前集中冲刺

---

## 3. 使用场景

| 场景 | 频率 | 典型行为 |
|------|------|----------|
| 学习新知识点 | 每天 | 浏览知识卡片，建立概念，然后做题巩固 |
| 每日做题 | 每天 | 完成当日新题 + 到期复习题 |
| 针对性刷题 | 按需 | 选择某个知识点集中练习 |

| 查看进度 | 随时 | 看看自己掌握了多少、还差多少 |

三类题型的反馈方式不同，但最终都归一到 `ReviewState`：

- 选择题：系统自动判断对错。
- 问答题：不进行 AI 评分，用户提交后查看参考答案并自行选择掌握状态。
- SQL 题：由 AI 根据业务要求和评分标准辅助判题；用户正常进入下一题视为接受结果，只有认为判题不合理时才调整或重新判题。

## 5. 核心概念定义

### 5.1 答题历史（Attempt）

**定义**：用户每一次做题的历史记录。用户提交答案时立即产生 Attempt。

不同题型的完成方式：

- 选择题：提交后系统自动判分，Attempt 直接完成。
- 问答题：提交后先保存用户答案并展示参考答案，等待用户选择「不会 / 模糊 / 基本掌握 / 熟练掌握」；完成自评后 Attempt 才完成。
- SQL 题：提交后保存用户 SQL，进入 AI 判题；AI 返回结果后，用户正常进入下一题即视为接受结果，也可以调整或重新判题。

**特征**：

- 同一道题可以产生多条 Attempt，每次重做都新增，不覆盖历史。
- Attempt 保存用户当次真实作答。
- 问答题额外保存用户当次自评的题目掌握状态。
- SQL 题保留 AI 原始判题结果以及最终采用的判题结果。

**用途**：学习历史、做题量统计、复习调度和历史回顾。

### 5.2 当前复习状态（ReviewState）

**定义**：用户对某道题当前的题目掌握状态（Question Mastery State）以及下次复习时间。

**特征**：

- 每道题最多一条 ReviewState。
- 历史 Attempt 不覆盖，ReviewState 持续更新。
- 选择题根据系统判分更新。
- 问答题根据用户自评结果更新。
- SQL 题根据最终采用的 AI 判题结果更新。

### 5.3 错题本（Wrong Book）

**定义**：一个产品视图，不是独立的数据实体。

默认展示题目掌握状态为：

```text
unmastered
vague
```

的题目，同时支持：

- 手动关注：强制显示。
- 手动忽略：仅从错题本隐藏，不影响 ReviewState 和间隔复习。

三者关系：

```text
Attempt（历史）
    │
    ├── 选择题：系统判分
    ├── 问答题：用户自评
    └── SQL题：AI判题结果
    │
    ▼
ReviewState（当前状态）
    │
    ├── 掌握状态
    └── next_review_date
    │
    ▼
Wrong Book（查询视图）
```

## 7. 每日学习任务模块

### 7.1 任务组成（MVP）

每日任务 = **到期复习题** + **固定数量新题**

| 类型 | 数量（默认） | 来源 | 说明 |
|------|-------------|------|------|
| 复习题 | 系统安排 | ReviewState 中 `next_review_date <= 今天` 的题目 | 优先推送最薄弱和已逾期题目，不计入新题数量 |
| 新题 | 5 道/天 | 从未完成过的题目 | 默认 3 选择 + 1 问答 + 1 SQL，可配置 |

### 7.2 任务状态

| 状态 | 说明 |
|------|------|
| 未开始 | 当日任务尚未开始 |
| 进行中 | 部分完成 |
| 已完成 | 当日任务全部完成 |
| 已跳过 | 用户主动跳过 |

### 7.3 每日学习流程

```text
进入今日任务
    │
    ├── 先做复习题
    │
    └── 再做新题
            │
            ├── 选择题
            │     提交 → 自动判分 → 答案解析 → 更新 ReviewState
            │
            ├── 问答题
            │     提交 → 展示参考答案/解析 → 用户自评掌握状态
            │     → 更新 ReviewState
            │
            └── SQL题
                  提交 → AI判题 → 展示结果
                  → 下一题默认接受 / 可调整或重新判题
                  → 更新 ReviewState
```

### 7.4 v1.1 增强（后续版本）

- 智能任务生成（基于知识点轮转 + 薄弱项分析）
- 知识点动态轮转
- 根据薄弱程度自动调整新题数量和难度

## 8. 知识卡片模块

### 8.1 定位

知识卡片不是课程系统，是**秋招快速学习的速记工具**。

目标：花 3-5 分钟浏览一张卡片，建立对一个知识点的基本认知，然后通过做题巩固。

### 8.2 卡片结构

| 字段 | 说明 |
|------|------|
| 一句话定义 | 用最简洁的话说明这个知识点是什么 |
| 核心原理 | 关键机制、原理，用 3-5 句话或要点列表 |
| 面试高频点 | 面试中经常被问到的内容 |
| 常见易错点 | 容易混淆或记错的内容 |
| 关联题目 | 链接到该知识点下的练习题 |

### 8.3 卡片示例（结构示意）

```
┌────────────────────────────────────────────┐
│  知识卡片：[知识点名称]                [下一题 →] │
├────────────────────────────────────────────┤
│                                            │
│  📌 一句话定义                               │
│  （用最简洁的语言描述）                       │
│                                            │
│  🔍 核心原理                                 │
│  • 要点 1                                   │
│  • 要点 2                                   │
│  • 要点 3                                   │
│                                            │
│  🎯 面试高频点                               │
│  • 高频考点 1                                │
│  • 高频考点 2                                │
│                                            │
│  ⚠️ 常见易错点                               │
│  • 易错点 1                                  │
│  • 易错点 2                                  │
│                                            │
│  📝 关联题目（N 道）                          │
│  • [题型] 题目标题                            │
│  • [题型] 题目标题                            │
│                                            │
│  [开始做题 →]  [返回知识点列表]                │
└────────────────────────────────────────────┘
```

### 8.4 知识卡片数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 稳定卡片 ID |
| knowledge_point_id | String | 关联知识点 ID |
| one_line_definition | Text | 一句话定义 |
| core_principle | Text | 核心原理 |
| interview_highlights | Text | 面试高频点 |
| common_mistakes | Text | 常见易错点 |
| related_question_ids | JSON | 关联题目 ID 列表 |

### 8.5 内容维护方式

知识卡片采用 AI 辅助生成 + 人工审核维护的方式。知识卡片属于结构化学习内容，与题目一起通过内容文件维护，通过初始化/导入流程进入系统。

### 8.6 与做题的联动

- 做题反馈页面显示"薄弱知识点"，点击可跳转到对应知识卡片
- 知识卡片底部显示关联题目，点击可直接做题
- 错题本中每道题可关联知识卡片，方便回顾

### 9.2 做题流程

```

├── ✅ 正确 / ❌ 错误
```

## 10. 问答题模块

### 10.1 定位

问答题用于训练**自己组织语言回答面试问题**的能力。

MVP 不对问答题进行 AI 打分。用户必须先独立作答，提交后系统再展示参考答案，由用户根据自己的实际回答情况自行判断掌握状态。

### 10.2 题目结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 稳定题目 ID |
| content | Text | 问题内容 |
| reference_answer | Text | 参考答案 |
| explanation | Text | 可选补充解析 |
| knowledge_point_id | String | 主知识点 |
| related_knowledge_point_ids | JSON | 关联知识点 |
| difficulty | Integer | 难度等级（1-5） |
| tags | JSON | 标签 |

**MVP 不需要**：

- `scoring_rubric`
- 得分点分值
- AI 问答评分
- AI 知识点命中分析

题目录入时只需要保证问题、参考答案及知识点关系经过人工审核。

### 10.3 做题流程

```text
显示问题
    │
    ▼
用户输入自己的答案
    │
    ▼
点击提交
    │
    ├── 创建 Attempt
    └── 保存用户原始答案
    │
    ▼
显示：
├── 我的答案
├── 参考答案
├── 补充解析（如有）
└── 关联知识卡片
    │
    ▼
用户自行选择当前掌握状态：
[不会] [模糊] [基本掌握] [熟练掌握]
    │
    ▼
Attempt 完成
    │
    ▼
ReviewState 更新
    │
    ▼
安排下次复习
```

### 10.4 自评原则

用户根据自己的实际回答与参考答案进行对照：

| 自评状态 | 建议判断 |
|---------|---------|
| 不会 `unmastered` | 基本答不出来，或核心概念明显错误 |
| 模糊 `vague` | 知道大概方向，但关键点缺失较多 |
| 基本掌握 `familiar` | 核心内容基本能说清楚，但细节或表达还不够完整 |
| 熟练掌握 `mastered` | 能较完整、准确、有条理地独立回答 |

系统不强制校验用户自评是否“客观正确”。自评是问答题进入复习算法的最终输入。

### 10.5 历史回顾

每次重做问答题都会产生新的 Attempt，因此后续可以查看：

```text
第一次：自己的答案 → 不会
第二次：自己的答案 → 模糊
第三次：自己的答案 → 基本掌握
第四次：自己的答案 → 熟练掌握
```

这样可以直接观察面试表达能力的提升过程。

## 11. SQL 手写题模块

### 11.1 题目结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String | 稳定题目 ID |
| content | Text | 题目描述（业务场景） |
| table_schema | Text | 建表语句 / 表结构说明 |
| field_description | Text | 字段含义说明 |
| business_requirement | Text | 业务需求描述（主要判题依据） |
| expected_sql | Text | 参考 SQL，仅供理解题意和学习参考 |
| scoring_criteria | JSON | 评分标准（主要判题依据） |
| knowledge_point_id | String | 主知识点 |
| related_knowledge_point_ids | JSON | 关联知识点列表 |
| difficulty | Integer | 难度等级（1-5） |
| tags | JSON | 标签 |

### 11.2 做题流程

```text
显示题目
    │
    ├── 业务描述
    ├── 表结构
    ├── 字段说明
    └── 业务要求
    │
    ▼
用户手写 SQL
    │
    ▼
点击提交 → 创建 Attempt
    │
    ▼
AI 根据 business_requirement + scoring_criteria 判题
    │
    ▼
显示：
├── 得分
├── 正确逻辑
├── 错误 / 遗漏逻辑
├── 知识点分析
├── 参考 SQL
└── 修改建议
    │
    ├── [下一题] → 默认接受本次 AI 判题结果
    ├── [调整结果] → 用户修正后完成
    └── [重新判题] → 对同一 Attempt 再次调用 AI
    │
    ▼
最终结果更新 ReviewState
```

不要求用户每道 SQL 题额外点击一次“确认评分”；正常进入下一题即视为接受。

### 11.3 AI 判题依据

主要依据：

```text
business_requirement
+
scoring_criteria
```

`expected_sql` 只是参考答案，不允许依据用户 SQL 与参考 SQL 的文本或结构相似度直接判断正确性。

允许存在多种满足业务要求的正确 SQL 写法。

AI 重点检查：

- SQL 语法和函数使用
- JOIN 关系与条件
- WHERE 过滤
- GROUP BY / 聚合
- 窗口函数
- 业务条件完整性
- 是否真正满足题目要求

SQL 不连接真实业务数据库执行。

### 11.4 AI 结果与最终结果

系统必须区分：

```text
AI Raw Assessment
        ↓
默认接受 / 用户调整 / 重新判题
        ↓
Final Result
```

AI 原始结果永久保留。

正常点击“下一题”：

```text
final_score_source = ai_confirmed
```

用户调整：

```text
final_score_source = user_adjusted
```

只有最终结果用于更新 ReviewState。

## 12. 错题本模块

### 12.1 定位

错题本是一个**产品视图**，不是独立数据实体。

```text
Wrong Book
=
Question
+
ReviewState
+
QuestionPreference
```

### 12.2 自动进入规则

| 题型 | 自动进入错题本的依据 |
|------|---------------------|
| 选择题 | 系统判错，掌握状态进入 `unmastered` / `vague` |
| 问答题 | 用户自评为 `unmastered` / `vague` |
| SQL 题 | 最终判题结果使掌握状态进入 `unmastered` / `vague` |

此外支持：

- `follow`：用户手动关注，无论掌握状态如何都展示。
- `ignore`：从错题本隐藏，但不改变 ReviewState 和复习调度。
- `auto`：按系统默认规则判断。

### 12.3 页面展示

每道题至少展示：

- 题型
- 关联知识点
- 当前题目掌握状态
- 最近一次 Attempt
- 下次复习日期
- 重做入口
- 知识卡片入口

问答题展示最近一次**自评状态**，不展示不存在的“AI 得分”。

### 12.4 自动脱离

达到：

```text
familiar
mastered
```

后自动从 Wrong Book 中移除，但手动 `follow` 除外。

退出错题本不等于停止复习。

## 13. 间隔复习模块

### 13.1 复习触发

- 每日任务自动加入 `next_review_date <= 今天` 的题目。
- 用户可从错题本或知识点页面主动重做。
- 掌握状态为熟练也仍会继续间隔复习，只是间隔更长。

### 13.2 Question Mastery State

```text
unmastered    不会
vague         模糊
familiar      基本掌握
mastered      熟练掌握
```

### 13.3 不同题型如何产生 ReviewState 输入

**选择题**

```text
系统自动判分
→ 复习算法计算掌握状态
```

**问答题**

```text
提交答案
→ 查看参考答案
→ 用户直接选择 Question Mastery State
→ 复习算法根据该自评状态安排复习阶段和日期
```

问答题不经过得分阈值转换。

**SQL题**

```text
AI判题
→ 默认接受或用户调整
→ 得到最终得分
→ 复习算法根据最终得分计算掌握状态
```

### 13.4 具体算法

具体间隔、复习阶段、SQL 分数阈值、连续成功规则等由：

```text
docs/REVIEW_ALGORITHM.md
```

统一定义。

PRD 不重复写死算法实现。

## 14. 学习统计模块

### 14.1 时间维度

MVP：

- 今日
- 本周
- 累计

### 14.2 统计内容

总体：

- 做题数量
- 学习天数
- 到期复习完成情况
- Question Mastery State 分布

按题型：

**选择题**

- 做题量
- 正确率

**问答题**

- 做题量
- 自评状态分布
- 从不会 → 模糊 → 基本掌握 → 熟练掌握的变化情况

问答题不统计“平均 AI 分数”或“正确率”。

**SQL题**

- 做题量
- AI 最终评分平均值
- 各掌握状态分布

### 14.3 Knowledge Point Mastery Score

学习统计继续支持多级知识点掌握率，例如：

```text
Spark                  68%
├── RDD                85%
├── Shuffle            42%
└── Spark SQL          75%
```

掌握率由各题目的 ReviewState 动态计算。

### 14.4 后续版本

趋势图、雷达图、月度学习报告等仍放到后续版本。

### 15.2 知识点数据结构

| 字段 | 类型 | 说明 |
|------|------|------|

### 15.3 知识点与掌握率

- 每个细分知识点（叶子节点）的 Knowledge Point Mastery Score = 该知识点下所有题目的 Question Mastery State 映射为分值后加权平均，最终以百分比呈现

- 学习统计页面展示完整的多级掌握率树
- Question Mastery State 到分值的映射规则留到复习算法设计阶段确定

## 18. MVP 范围

**MVP 目标**：每天真正能用起来，服务秋招冲刺。

### MVP 包含

| 功能 | 范围 |
|------|------|
| 首页 | 今日任务、待复习和基础统计 |
| 知识卡片 | 快速学习并关联题目 |
| 知识点体系 | 多级知识点浏览 |
| 选择题 | 自动判分、答案解析、自动进入复习算法 |
| 问答题 | 自己作答、提交后展示参考答案、用户自评掌握状态 |
| SQL 题 | AI 辅助判题、展示分析；下一题默认接受，可调整/重判 |
| 错题本 | 基于 ReviewState 的查询视图 |
| 间隔复习 | 每日推送、掌握状态和复习日期更新 |
| 学习统计 | 今日 / 本周 / 累计；知识点掌握率 |

### 内容维护

MVP 不开发题库管理后台。

内容文件维护：

- 选择题：问题 + 选项 + 答案 + 解析
- 问答题：问题 + 参考答案 + 可选解析
- SQL题：业务要求 + 表结构 + 参考 SQL + scoring criteria
- 知识卡片：Markdown

内容可以由人工、外部资料或 AI 辅助整理，但进入系统前必须人工审核。

### MVP 不包含

- 智能知识点轮转
- 难度自适应
- 题目收藏
- 数据导出
- 面试冲刺模式
- 问答题 AI 强制评分

## 20. 已确认的设计决策

### Q1：题目来源

MVP 通过结构化内容文件维护。人工整理、外部资料或 AI 辅助生成均可，但进入系统前必须人工审核。

### Q2：MVP 的 AI 用在哪里

运行时 AI 只作为 **SQL 手写题判题能力**。

问答题 MVP 不调用 AI 评分。

### Q3：问答题如何评估

采用：

```text
自己作答
→ 提交
→ 展示参考答案
→ 用户自评：
不会 / 模糊 / 基本掌握 / 熟练掌握
```

用户自评结果直接作为问答题复习算法输入。

### Q4：每日新题数量

默认：

```text
3 道选择题
1 道问答题
1 道 SQL 题
```

总计 5 道，可配置。到期复习题不计入新题数量。

### Q5：知识卡片

AI 辅助生成 + 人工审核，通过内容文件维护。

### Q6：SQL 判题

SQL 使用统一 LLM Service。具体模型厂商不在 PRD 绑定。

判题主要依据：

```text
business_requirement
+
scoring_criteria
```

参考 SQL 不是唯一正确答案。

### Q7：学习统计

MVP 提供今日、本周、累计。

问答题统计自评掌握状态，不统计 AI 平均得分。
